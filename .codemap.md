## Module Map

### `di/ServiceLocator.kt` [config]
- **Does**: One-time manual DI init from `Application.onCreate`. Builds `OkHttpClient` (DNS-over-HTTPS via Cloudflare to dodge ISP DNS blocks of TMDB, `ApiAuthInterceptor`, logging), two `Retrofit` instances (TMDB + fanart.tv), and the two repositories + `FavoritesStore`.
- **Exports**: `okHttpClient`, `movieRepository`, `posterRepository`, `favoritesStore`, `init(context)`
- **Depends on**: `data/remote/*`, `data/repository/*`, `data/local/FavoritesStore`

### `data/repository/MovieRepository.kt` [service]
- **Does**: Movie/TV lists (trending/popular/top-rated/now-playing, both media types), single-item details, multi-search as a `Paging3` `Flow<PagingData<Movie>>` via `TmdbPagingSource`.
- **Exports**: `MovieRepository`, `TmdbPagingSource`, `TmdbMovieDto.toMovie()`
- **Depends on**: `data/remote/TmdbApi`, `data/remote/dto/Dtos`, `domain/model/Models`

### `data/repository/PosterRepository.kt` [service]
- **Does**: For a title, fetches TMDB + fanart.tv posters in parallel (`async`/`coroutineScope`), dedupes by URL, ranks by pixel count (highest-res first, TMDB over fanart on ties, textless preferred), pins the caller's preferred poster to index 0. Caches results in an `LinkedHashMap` (max 40 entries) keyed by `id|type|preferredPath` so detail screen and fullscreen viewer see an identical ordered list.
- **Exports**: `PosterRepository.postersFor(id, type, preferredPath)`
- **Depends on**: `data/remote/TmdbApi`, `data/remote/FanartApi`, `data/ImageUrl`, `domain/model/Models`

### `data/remote/ApiAuthInterceptor.kt` [middleware]
- **Does**: Per-request-host auth injection — TMDB gets Bearer header (v4 token) or `?api_key=` (v3 key); fanart.tv gets `?api_key=`. Image CDN hosts get nothing.

### `data/local/FavoritesStore.kt` [repo]
- **Does**: JSON-serialized `List<FavoriteMovie>` in a single Preferences DataStore key (no Room/codegen). `favorites: Flow`, `toggle(movie)`.

### `ui/nav/Routes.kt` [route]
- **Does**: `@Serializable` type-safe nav destinations (`HomeRoute`, `SearchRoute`, `FavoritesRoute` as objects; `DetailRoute`, `FullscreenRoute` as data classes carrying just enough to render the shared-element hero before full data loads). Also defines `heroOrVariantKey`/`variantThumbKey` — the shared-element key scheme that lets the fullscreen pager and the detail variants strip morph to/from the exact tapped thumbnail.

### `ui/home` / `ui/search` / `ui/favorites` / `ui/detail` [service+ui pairs]
- Each screen follows the same shape: a `ViewModel` (constructed via `util/viewModelFactory` with `ServiceLocator` defaults) exposing `StateFlow<UiState>`, and a `@Composable` Screen that reads it via `collectAsStateWithLifecycle()`. All screens participate in one shared `SharedTransitionLayout` (declared once in `PosterNav.kt`) so poster thumbnails morph into the detail hero and into the fullscreen viewer.
- `DetailViewModel` additionally exposes `isFavorite: StateFlow<Boolean>` derived from `FavoritesStore.favorites`, and `toggleFavorite()`.

### `ui/fullscreen/FullscreenPosterScreen.kt` [ui]
- **Does**: Loads the full poster-variant list directly from `ServiceLocator.posterRepository` (bypassing a ViewModel, via `produceState`), shows the tapped poster immediately via shared element while loading, then a `HorizontalPager` of `ZoomableImage`s once ready. Save/wallpaper act on the currently paged poster.

### `util/ImageActions.kt` [util]
- **Does**: Decodes a URL to a software `Bitmap` via the shared Coil `ImageLoader`; saves to `Pictures/PostersHub` (MediaStore on API 29+, direct file write + registration on 24-28); sets system/lock wallpaper via `WallpaperManager`.

